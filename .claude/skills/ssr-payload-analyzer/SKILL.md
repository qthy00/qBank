# SSR Payload 分析器

用于评估 Nuxt/Vue SSR 页面中数据传递策略的技能，帮助决定哪些数据应该随 HTML payload 传递，哪些应该在客户端异步获取。

## 何时触发

- 用户询问 SSR payload 优化
- 用户需要评估页面数据传递策略
- 评审 SSR 页面代码时涉及数据获取逻辑
- 页面首屏性能优化相关讨论
- 用户提到 "payload"、"水合"、"hydration"、"useAsyncData"、"useFetch"

## 核心检查清单

对 SSR 页面的每个数据项，按以下四问进行评估：

### 1. 水合必要性检查
**问题**：客户端水合阶段是否会因为缺数据而重复请求接口？
- **如果会** → 倾向保留 payload，避免重复请求
- **如果不会** → 可考虑客户端异步加载

### 2. 首屏交互检查
**问题**：客户端是否需要一份结构化状态树来驱动首屏交互？
- **如果需要** → 倾向保留 payload，确保首屏可交互
- **如果不需要** → 可考虑延迟加载

### 3. 数据体积检查
**问题**：这份数据是否大到影响解析与水合？
- **如果是** → 按字段裁剪 / 延迟加载 / 拆分路由策略
- **如果否** → 可保留 payload

### 4. 安全敏感检查
**问题**：是否包含敏感信息或用户可控内容？
- **如果包含** → 必须脱敏与安全序列化
- **如果不包含** → 正常处理

## 分析流程

```
1. 识别页面所有数据获取点（useAsyncData、useFetch、asyncData 等）
2. 对每个数据项应用四问检查
3. 综合评估给出建议
4. 输出优先级排序：必须payload > 建议payload > 可选延迟 > 建议延迟
```

## 决策规则

### 必须使用 Payload（4问中至少2个通过）
- 水合必要性 ✅ + 首屏交互 ✅
- 水合必要性 ✅ + 数据体积 ✅（数据量小）
- 首屏交互 ✅ + 敏感数据需服务端处理

### 建议使用 Payload（4问中至少1个通过）
- 首屏交互 ✅（状态驱动 UI）
- 水合必要性 ✅（避免重复请求）

### 可选延迟加载（4问全部待定）
- 非关键业务数据
- 首屏不可见区域数据

### 建议延迟加载（以下任一满足）
- 数据体积 ❌（数据量大）
- 安全敏感 ❌（需客户端脱敏）
- 首屏交互 ❌ + 水合必要性 ❌

## Nuxt 特定实现参考

### 保留 Payload 的方式
```typescript
// 使用 useAsyncData 或 useFetch 会自动包含在 payload 中
const { data } = await useAsyncData('key', () => $fetch('/api/data'))
const { data } = await useFetch('/api/data')
```

### 延迟加载的方式
```typescript
// 客户端 only，不包含在 payload
const data = ref()
if (import.meta.client) {
  data.value = await $fetch('/api/data')
}

// 或使用 lazy 选项
const { data } = useLazyFetch('/api/data')
```

### 条件 Payload 策略
```typescript
// 根据数据量动态决定
const { data: list } = await useAsyncData('list', async () => {
  const result = await $fetch('/api/list')
  // 如果数据量超过阈值，返回空或精简版
  if (result.length > 100) {
    return { truncated: true, preview: result.slice(0, 20) }
  }
  return result
})
```

## 常见场景速查

| 场景 | 建议 | 理由 |
|-----|------|------|
| 用户登录状态 | 必须 Payload | 影响首屏 UI 渲染，水合必需 |
| 导航菜单 | 建议 Payload | 首屏可见，水合必需 |
| 文章详情 | 必须 Payload | SEO 需要，首屏内容 |
| 评论列表 | 建议延迟 | 非首屏关键，数据量大 |
| 推荐商品 | 延迟加载 | 非必需，可异步 |
| 用户配置 | 可选 Payload | 如主题设置影响首屏则保留 |
| 大量列表数据 | 建议延迟 | 数据体积问题 |
| 敏感用户信息 | 必须 Payload+脱敏 | 安全考虑，服务端处理 |

## 注意事项

1. **不要过度优化**：首屏关键数据应优先保证体验
2. **测试验证**：修改后务必测试首屏性能和交互
3. **渐进优化**：可先从明显的大数据项开始优化
4. **SEO 考量**：SEO 依赖的数据必须使用 payload
5. **错误处理**：延迟加载的数据需处理加载态和错误态
